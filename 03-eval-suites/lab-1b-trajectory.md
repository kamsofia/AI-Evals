## Part 2 · Three Audience Messages

### A. For Engineering (Jira ticket)
Acceptance Criteria: GIVEN a user query mentions pricing AND the response contains a $-amount, WHEN the amount does not match pricing_api.current_price, THEN block the response and trigger fallback message: "Live rates unavailable, please contact sales." Zero tolerance — test: 20 historical pricing queries must all match.

Note on current Layer 1 implementation: existing code check tests for the string "subject to change," not for price accuracy — this must be replaced with the $-amount vs. pricing_api.current_price comparison above. The current check would pass a wrong price that includes the right disclaimer, and fail a correct price missing it.

### B. For UX / Design
When the guardrail blocks a pricing response, insert the fallback message inline in the existing conversation thread (not a modal, not a new screen) with the "Contact Sales" CTA opening a new tab to the sales contact form, pre-filled with the user's original question as context. The conversation remains fully interactive — the user can immediately ask a follow-up, rephrase, or ask about a different topic without restarting. If the user's next message also references pricing and the guardrail fires again, repeat the same fallback (no escalating language, no "I still can't help with that" — treat each trigger identically to avoid the assistant seeming broken).
