## Fallback methods (non-Level 3 items)

### L2 · Context Specificity (UX Trust · P1)
- **Method:** Weekly audit of 100 sampled outputs, checked against the original instruction (e.g., "isolate negatives" vs. "summarize all reviews") to catch instruction-following drift.
- **Why this fallback is defensible:** This is a completeness/nuance failure, not a fabrication. The agent's answer is still factually correct, just less precise than requested. It creates a slow-building quality/churn risk, not an acute one, so a weekly sample is enough to catch a drifting pattern before it compounds into a client complaint. Paying 10x for continuous monitoring on a quality issue (versus a fabrication or compliance issue) isn't proportionate to the risk.

### L2 · Data Bias (Fairness · P2)
- **Method:** Weekly audit sampling outputs specifically for regional balance (US vs. APAC representation) in summarized insights.
- **Why this fallback is defensible:** This is a skew that builds up over many outputs, not a single-instance catastrophic error. A weekly sample is enough to catch the pattern before it meaningfully distorts a strategic view, and P2 severity doesn't justify continuous automated cost at this stage.

### L1 · Cost Overruns (Latency · P3)
- **Method:** Code-based gate at deploy time checking token usage per query against a fixed ceiling; flags/blocks outliers before they ship.
- **Why this fallback is defensible:** This is a pure operational cost problem. It doesn't touch data accuracy, client trust, or compliance. A cheap deterministic check is proportionate; there's no case for spending 20x on continuous monitoring for a budget-line risk.
